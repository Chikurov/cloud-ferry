# Аудит Cloud Ferry

15 ноября 2026. Текущий продукт — версия 0.3.1, flow v3. Четыре пути: подключение, скачивание, аккаунт, системные состояния. Ниже — где пользователь застревает, какие дыры есть в поведении и что поменять в интерфейсе.

В тот же день в коде исправлено: неверный пароль не просит ждать 2–3 часа; папки видны сразу, метка «Папка есть на сервере»; ошибка папки на сервере не отправляет входить в Диск; закрытие окна отменяет оценку в браузере. Запуск передаёт `clientToken`.

## Где трение

| Путь | Оценка | Что происходит |
|---|---|---|
| Запуск, пустой экран, офлайн, активное скачивание, аккаунт, телефон | гладко | Один следующий шаг, данные на экране остаются |
| Новое скачивание | заметно | Три шага каждый раз, оценка объёма, лимит 20/100, фильтр без пояснения |
| Пауза, ошибка, восстановление после перезапуска | заметно | Оборванный файл качается заново, «Повторить» запускает всю задачу, после перезапуска нужно нажать «Продолжить» |
| Выход | заметно | Не сказано, что оборванный файл неполный. Задания остаются в хранилище, но после отключения диска их нельзя продолжить |
| Подключение | высокое | Пароль приложения требует Яндекс 360. Неверный пароль показывается как неверные данные. Токен — отдельная техническая процедура. Шаг папки не объясняет, что это папка Umbrel |

## Баги и дыры

1. **Оборванный файл начинается сначала.** Пауза, «Продолжить», «Повторить» и перезапуск приложения сохраняют уже целые файлы. Файл, который не докачался, качается с нуля. На большом файле это выглядит как долгое скачивание без движения процента.

2. **Обход объёма внутри rclone не проверен.** Закрытие окна и уход со шага обрывают запрос в браузере, незавершённый ответ в новый выбор не попадает. Останавливается ли уже начатый обход внутри rclone, по коду HTTP не видно.

3. **Списки обрезаны.** Дерево — первые 500 папок, файлы в папке — первые 200. Следующей страницы нет. Всё, что дальше, можно взять только вместе со всей папкой.

4. **На главном одна задача.** Видна активная или последняя. Остальные активные и прошлая история с экрана недоступны.

5. **Проверка целостности не доходит до экрана.** Статус «Проверяем файлы» в интерфейсе зарезервирован, сервер его не присылает. Результат ручной проверки в карточку не попадает, остановить такую проверку нельзя.

6. **Режим с удалением есть в API.** Интерфейс всегда скачивает в режиме добавления: в облаке только чтение, на сервере файлы не удаляются. Отдельный режим синхронизации с удалением лишнего сервер принимает. В корне `/downloads` он закрыт, во второй папке назначения — нет.

7. **Прогресс виджета без входа.** `/api/widget` отвечает без cookies и отдаёт сводку текущего скачивания. Так устроен домашний экран Umbrel: у API нет своего секрета, запрос с сети домашнего сервера проходит.

## Недочёты

- Каждый новый запуск начинается с «Куда сохранить», даже если папка с прошлого раза на месте.
- Пометка «Папка есть на сервере» есть у папок и не означает, что скачаны все файлы. У отдельных файлов её нет: сервер сверяет только папки. Число элементов в папке назначения — это не число файлов, которые будут пропущены.
- Фильтр «Показать уже скачанные» по умолчанию включён, все папки видны. Если его выключить, невыбранные совпадения скрываются, уже выбранная папка остаётся. Это правило на экране не написано.
- Ошибка «нужен Яндекс 360» не ведёт на «Яндекс ID» или «Токен».
- Подтверждение выхода говорит, что скачивание остановится и файлы останутся. Про неполный файл и про то, что продолжить задания после отключения нельзя, текста нет. Сами задания из хранилища при этом не удаляются.
- В приложении один аккаунт. Новое подключение заменяет старое. Пока идёт скачивание, заменить подключение нельзя: сначала пауза.
- Альбомы «Фото» и история версий не скачиваются.
- Диалог на компьютере узкий (480 px), файлы открываются под строкой папки. На телефоне лист на весь экран, это читается нормально.
- Между шагами прокрутка возвращается наверх. Раскрытие дерева и выбор сохраняются.

## Лишние описания флоу

Рабочие описания — три файла:

- `USER-GUIDE.md` — что делать человеку
- `flows.md` — сценарии и трение
- `ARCHITECTURE.md` — сервер, тома, восстановление, безопасность

Остальное в `docs/` повторяет эти пути или фиксирует прогон:

- `flows-architecture.md` — те же четыре пути, что в `flows.md`
- `ui-standards.md` — нормы плюс длинное описание экрана скачивания, которое уже есть в `flows.md`
- `flow-v3-audit.md` — предложение по шагам, те же три шага
- `flow-v3-apply.md` — журнал, что из предложения уже сделано
- `flow-audit.md` — прогон интерфейса 14 ноября
- `design/flow-v2.md` — предыдущий макет тех же трёх шагов

Хвост «короткий вход, пагинация, отмена оценки, история, пометка файлов» записан в `flows.md`, `flows-architecture.md` и `flow-v3-apply.md`. Достаточно одного списка в `flows.md`.

Запуск передаёт `clientToken`: повтор с тем же ключом возвращает уже созданную задачу. «Повторить» после ошибки запускает задачу заново: целые файлы пропускаются, оборванный качается сначала.

## Интерфейс

1. **Повторное скачивание открывается на «Что скачать».** Последняя папка — строка «Сохранить в» и «Изменить». Шаг «Куда сохранить» открывается, когда папки нет.
2. **Проверка — три строки.** «Источник», «Папка на сервере», «К скачиванию». «Свободно» появляется, когда число известно. При «Не хватает …» кнопка «Скачать» недоступна. Пока объём считается или оценка не удалась, на месте объёма строка «Объём пока неизвестен», кнопка остаётся доступной: сервер сам останавливается на 90 % свободного места.
3. **Фильтр с одной подписью.** «Скрыты папки, которые уже есть. Выбранные остаются в списке». Отдельного обещания перекачать нет.
4. **Лимит над кнопками.** «Можно выбрать не больше 20 папок» и «Можно выбрать не больше 100 отдельных файлов». «Назад», «Проверить выбор», «Закрыть» и снятие галки в этот момент работают. У «Весь диск» в меню «Ещё» короткая оговорка: лимит 20/100 на этот режим не действует. Открытие меню режим не переключает.
5. **Мастер подключения.** На шаге папки фраза «Сюда, в папку Umbrel, сохранятся файлы». На сообщении про Яндекс 360 рядом действие перехода на вход через Яндекс или по токену.
6. **Выход.** В подтверждении: скачивание остановится, целые файлы останутся, оборванный файл неполный, задания в приложении исчезнут.
7. **После «Не удалось».** Список файлов и «Скопировать список» остаются. Кнопка называется «Запустить снова», рядом текст: целые файлы будут пропущены. Отдельное «Повторить нескачанное» — когда сервер сможет отдать только список сбоев.
8. **Карточка «Сейчас».** Один статус, одна кнопка. «Пауза» после руки и после перезапуска различается текстом причины. Процент, скорость и остаток видны, когда они есть. Пока объём неизвестен — «Считаем…».
9. **Ширина на компьютере.** Диалог шире 480 px, список файлов справа от дерева. На телефоне шаги, лист на весь экран и панель файлов под папкой остаются как сейчас.
