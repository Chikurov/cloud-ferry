# UI-стандарты Cloud Ferry

Действуют для UI-kit **v5** в `internal/httpapi/web/{index.html, app.js, style.css}`.
UX-проход 14.11.2026 внедрил обратную связь после реального использования:
первый экран, экран авторизации, подсказки, окно выбора папки, экран успеха,
пустое состояние «Сейчас», сетку «Хранилища», выбор папок в облаке и меню
аккаунта. Проход 15.11.2026 добавил вход через Яндекс по коду подтверждения
(device flow на серверных кредах) как основной способ подключения.
Основание — система правил **AI Agent Knowledge System 2.9.0** (14.11.2026):
`~/.dsh/README.md`, `~/.dsh/rules/frontend-ux.md`, `~/.dsh/knowledge/ui-design/INDEX.md`
и главы `color-materials`, `accessibility`, `controls-components`, `layout-density`,
`typography-writing`, `states-recovery`, а также
`~/.dsh/knowledge/engineering/russian-typography.md`.
Здесь зафиксировано, что именно из этих правил применено в Cloud Ferry.

## Экран

Один экран, две колонки по центру (контейнер 720 px). Слева 400 px — «Сейчас»
и «Новое скачивание» друг под другом; справа 300 px — категория «Хранилище»
с двумя маленькими плитками. До 760 px — одна колонка в порядке чтения:

| Ячейка | Содержимое |
|---|---|
| **Сейчас** | статус-пилюля, крупный процент, тонкий прогресс, скорость и ETA, «3 папки · 12,2 из 29,0 ГБ → /downloads/yandex», «Приостановить» / «Продолжить» / «Повторить»; после сбоя — частичный результат «Не скачались: N» и «Скопировать список». Если скачиваний не было — «Скачиваний пока нет» и действие «Начать скачивание», которое фокусит форму |
| **Новое скачивание** | форма прямо в ячейке: источник в облаке — кнопка-сводка (иконка + «Весь Диск» / «/Фотографии» / «3 папки» + «Выбрать» / «Изменить»), папка на сервере (иконка + путь), кнопка «Скачать». Режима скачивания нет: всегда `copy` |
| **Хранилище** | заголовок-категория `.cell-head` (иконка + «Хранилище»), внутри — две отдельные плитки: «Яндекс Диск» и «Сервер Umbrel». В каждой одна строка `иконка · название · значение справа` (крупное число и «из 214 ГБ» по базовой линии), тонкий метр и подпись «свободно 76 ГБ». Контейнер плиток: `max-height: 180px`, `overflow-y: auto` |

Диалога скачивания и истории скачиваний нет. Без аккаунта — пустой экран с
плиткой **«Подключить диск»** (без подписи про аккаунт Яндекса). Главное
действие всегда одно и цветное; опасное («Выйти») объяснено и требует
отдельного нажатия. Красный цвет оставлен только опасным действиям и
подтверждению выхода.

## Данные: только добавление и обновление

Интерфейс всегда отправляет `mode=copy`: приложение только добавляет новые
файлы и обновляет существующие. Оно ничего не удаляет — ни в облаке, ни на
сервере. Режим синхронизации с удалением (`sync`) остаётся возможностью API и
темой будущей итерации; в главном экране его нет, подсказок про удаление тоже
нет. Это правило интерфейса, а не только настройка: переключателя режима в
UI-kit v5 не существует.

## Токены

Семантика задана CSS-переменными в начале `style.css`:

- отступы — шкала **4/8/12/16/20/24** (`--space-1…6`, `--gutter`, `--gap`, `--pad`);
- радиусы — **16 — поверхности, 10 — поля и кнопки, 8 — мелкие элементы,
  pill — чипы, пилюли и полосы**: `--r-xs` 4, `--r-sm` 8, `--r-control` 10,
  `--r-lg` / `--r-cell` 16, `--r-pill` 999. Ячейки и диалоги — 16, поля,
  кнопки, сводка источника и строки папок — 10, чипы и статус-пилюли — pill;
- высота контролов — `--control-h: 44px` (поля, кнопки, «Обзор»);
- типографика — **12/13/14/16/20/24** (`--text-xs…2xl`);
- цвет — `--ink`, `--ink-soft`, `--muted`, `--accent*`, `--ok`, `--warn`,
  `--amber`, `--err`;
- границы — `--hairline`, `--line`, `--border-strong`, `--border-control`
  (`rgba(16,24,40,.48)`, hover `.62`, только 1 px, 3,2:1 по WCAG 1.4.11),
  `--border-check` (`#8c9098` для чекбоксов), `--border-danger`,
  `--amber-border`;
- фокус — `--focus: #0059bd`, у полей дополнительно синий ring 3 px
  (`--focus-ring: rgba(0,94,250,.22)`);
- акцент — `--accent: #005efa`, hover `#0052d6`; пройденный сегмент шага —
  `--step-done: #89a7ff` (только графика), предупреждения-иконки — `--orange:
  #fc3f1d` (только графика, текст — `--amber`).

Компоненты используют токены, а не случайные значения одного экрана.

## Типографика и русский текст

- Основной текст 14/20; вторичный 12/18; подписи полей `.control-label` —
  12/16, uppercase, tracking `.04em` — остались только в мастере подключения.
- Поля `input/select/textarea`: **14/20 на десктопе и 16/20 на мобильном**
  (`@media (max-width: 700px)`), одинаковый цвет placeholder `#6b7280` и
  одинаковая высота 44 px с кнопками; 16 px на мобильном не даёт iOS
  увеличивать страницу при фокусе.
- Заголовок ячейки 14/20, `.brand-name` 15/20 (на мобильном не уменьшается),
  `.modal-title` и `.setup-title` — 20/26, `.setup-title--done` — 20/26
  внутри зелёной плашки успеха, процент в «Сейчас» — 24/30. В плитке
  «Хранилища» число значения — 13/18 semibold, подпись — 12/18.
- Неразрывный пробел U+00A0 ставится в числовых связках: `5 ч 56 мин`,
  `14 ноября`, `42 %`, `76 ГБ`, `12 483 файла`, `20 папок`. Это делает
  `humanEta`, `formatWhen`, `humanBytes`, `humanPair`, `formatFiles`,
  `usageValuePair` и форматирование процентов; вручную строки не подменяются.
- Кавычки — «ёлочки»; интерфейс на русском, технические идентификаторы не
  локализуются. Команда обмена токена — технический текст в `<code>`.

## Пути

- Видимые пути всегда с прямым слэшем `/`: `displayPath` заменяет `\` на `/`
  только на отображении и в тексте ошибок, `displayCloudPath` добавляет
  ведущий `/`. API-формат и отправляемые значения не меняются.
- Длинные пути обрезаются с многоточием и полным значением в `title`:
  сводка источника, строка `→ /downloads/...` в «Сейчас», строки папок и
  текущий путь в пикере сервера; размер папки — рядом с названием, полный
  размер в `title` значения плитки. Поле назначения — обычный `input`,
  поэтому показывает путь прокруткой и хранит `title`.

## Плотность и адаптив

- `.cell { padding: 20px }`, `.cell-body { margin-top: 12px }`.
- Сетка: `--container: 720px`, `--col-main: 400px`, `--col-side: 300px`,
  gap 16 px; `.dashboard` — grid-areas `now/form` слева и `storage` справа,
  `justify-content: center`. На ≤760 px — одна колонка
  `now → form → storage`. На 1000×780 страница не прокручивается.
- «Сейчас» — всегда `min-height: 112px` (не прыгает между режимами);
  содержимое не меняет сетку. В работе: строка процента и «Приостановить»,
  под ней прогресс во всю ширину, затем скорость и ETA, затем
  «3 папки · 12,2 из 29,0 ГБ» и «→ /downloads/yandex». Пустое состояние —
  «Скачиваний пока нет» и «Начать скачивание» (secondary), фокус уходит на
  кнопку-сводку источника.
  «Скачать» — primary 44 px слева под полями.
- «Хранилище»: `.cell--storage` не задаёт min-height; `.storage-list` —
  `max-height: 180px; overflow-y: auto`, поэтому больше плиток прокручиваются
  внутри блока, а не растягивают экран. Плитка — grid
  `16px minmax(0,1fr) auto` с `align-items: baseline`: иконка, название и
  значение выровнены по одной базовой линии, значение прижато к правому краю,
  полоса занимает всю ширину, подпись «свободно …» — отдельная строка слева.
  Отступы у обеих плиток одинаковые.
- Мастер подключения: карточка `max-width: 520px`; переключатель способов
  входа — сетка из двух равных сегментов, когда доступен вход через Яндекс —
  его сегмент во всю ширину над двумя запасными; на ≤440 px — в один столбец;
  сегменты 38 px (44 px на тач-устройствах). Раскрытая инструкция по токену —
  компактная плашка, команда в `<code>` прокручивается внутри блока, страница
  при этом не расширяется. На 1000×780 открытая инструкция может требовать
  вертикальной прокрутки — это нормальное состояние длинного объяснения.
- `body`, `.shell`, `.setup` — `min-height: 100dvh`; страница не скроллится
  горизонтально на 390 px (проверяется скриншотом).
- `@media (pointer: coarse)`: тач-цели 44 px у `.method-option`, `.btn--sm`,
  `.btn--icon`, `.toast-close`, `.menu-item`, `.account-chip`, `.folder-expand`.
- `.modal-foot` переносится (`flex-wrap: wrap; row-gap: 8px`);
  `body:has(dialog[open])` блокирует прокрутку под диалогом;
  тосты учитывают `env(safe-area-inset-bottom)`.

## Цвет и контраст

- Светлая тема, холодный серо-голубой фон, один мягкий синий градиент, белые
  полупрозрачные поверхности, hairline-рамки, одна мягкая тень.
- Поля ввода/выбора: рамка `--border-control` — **1 px** `rgba(16,24,40,.22)`,
  hover `.34`, объём добавляет едва заметная внутренняя тень
  `inset 0 1px 2px rgba(16,24,40,.035)`; placeholder `#6b7280` (контраст
  текста ≥4,5:1); фокус — синий border и ring 3 px `--focus-ring`. Толщина
  рамки не увеличивается. Выбранный сегмент способа входа — белая заливка,
  рамка и текст `--accent`; чекбоксы папок — рамка `--border-check` `.48`
  (контраст нетекстового элемента ≥3:1).
- Состояние не передаётся только цветом: есть текст, пилюля, иконка или подпись.

## Статусы

| Состояние | Пилюля | Цвет |
|---|---|---|
| `running`, `verifying` | «Идёт скачивание» / «Проверяем файлы» | бледно-голубая заливка, синий текст |
| `done` | «Готово» | зелёная |
| `interrupted`, `canceled` | «Пауза» | жёлтая |
| `failed` | «Ошибка» | янтарная/оранжевая, не красная |
| `needs-auth` | «Нужен вход» | янтарная/оранжевая, не красная |
| `queued` | «В очереди» | нейтральная серая |

Точка внутри пилюли рисуется `currentColor` и всегда совпадает с цветом
текста. Красный (`--err`) остаётся только у опасных действий: «Выйти» в меню
и кнопка подтверждения выхода; ошибки полей и тосты об ошибках — янтарные.
Пилюля не единственный носитель статуса: он дублируется текстом и `#live`.

## Состояния

| Состояние | Реализация |
|---|---|
| Первый запрос | экран `#boot-view` «Загрузка…» с `aria-busy="true"` |
| Нет связи при старте | экран «Нет связи с сервером» + «Повторить» (`#offline-view`) |
| Пусто | плитка «Подключить диск» |
| Пусто в «Сейчас» | «Скачиваний пока нет» + «Начать скачивание» |
| Данные | ячейки «Сейчас»/«Хранилище», статус-пилюля, прогресс |
| Яндекс: ждём подтверждение | панель с кодом и таймером, `role="status"` «Ждём подтверждение…» |
| Яндекс: ошибка или истёк код | янтарная панель, «Получить новый код», фокус на кнопке |
| Частичный результат | при `job.failureCount` — «Не скачались: N» янтарным и «Скопировать список» в «Сейчас» |
| Ошибка формы | поле с `aria-invalid`/`aria-describedby` и янтарным текстом под контролом; общий сбой — баннер `#job-error` |
| Ошибка сервера | помечается только поле из `field` ответа; остальное — баннер |
| Ошибка в диалоге | inline-сообщение внутри диалога, не тост под top layer |
| Размеры папок недоступны | `POST /api/cloud/sizes` вернул 404/405 — размеры просто не показываются, список папок работает; пока ответа нет — «…» |
| Лимит папок | 21-я не отмечается, в подвале «Можно выбрать не больше 20 папок» |
| Offline после старта | янтарная точка в шапке + тост «Нет связи с сервером» с повтором |
| Отправка | кнопка с `aria-busy` и спиннером, поля блокируются логикой |
| Успех | тост `role="status"`, автоскрытие 6000 мс с паузой на hover/focus |
| Ошибка/предупреждение | тост `role="alert"`/`status` без автоскрытия, с действием |

Статусы объявляет один sr-only регион `#live` (`role="status"`,
`aria-live="polite"`, `aria-atomic="true"`). Перерисовываемые пилюли,
offline-точка и шаги мастера собственных live-ролей не имеют. Исключение —
строка состояния Яндекс-входа: у неё собственный `role="status"` и
`aria-live="polite"`, потому что это локальное состояние панели, а не статус
задания.

## Доступность

- Видимый фокус у всех интерактивных элементов (`:focus-visible`, `--focus`).
- Поля связаны с подписями: `<label>`, `aria-labelledby` или `aria-label`;
  ошибка — `aria-invalid="true"` + `aria-describedby` на узел с текстом,
  состояние снимается при вводе. На главном экране видимых подписей
  «Из облака»/«На сервер» нет — поля подписаны иконками, placeholder и
  `aria-label`, сводка источника — динамическим `aria-label`.
- Способ входа — `role="radiogroup"` из двух или трёх `role="radio"` с
  `aria-checked` и roving tabindex; стрелки/Home/End двигают выбор, клик
  оставляет фокус на выбранном сегменте. Переключение сохраняет введённые
  логин, пароль и токен. У Яндекс-входа свой `role="status"` (`aria-live`
  `polite`) для «Ждём подтверждение…» / ошибки / истечения и программный фокус:
  на коде после получения, на кнопке повтора после ошибки.
- Кнопка «Как получить токен?» — `aria-expanded` + `aria-controls`; текст
  инструкции остаётся в потоке, команда копируется кнопкой «Скопировать»
  (fallback на выделение при запрете clipboard).
- Автозаполнение: логин — `autocomplete="username"` и `name="username"`,
  пароль — `autocomplete="current-password"` и `name="password"`; обе формы
  подключения настоящие `<form>` с submit-кнопкой, поэтому менеджер паролей
  видит отправку. Токен не подсказывается браузером (`autocomplete="off"`).
- Диалоги: `aria-labelledby`, `aria-describedby`, `aria-busy` во время
  загрузки/действия, стартовый фокус на заголовке (`tabindex="-1"`), возврат
  фокуса на инициатора; после «Выбрать эту папку» фокус уходит в поле пути,
  а не на «Обзор».
- Меню аккаунта — roving tabindex: Tab не перебирает все пункты, стрелки/Home/End
  двигают фокус, Escape закрывает, при `hashchange` меню закрывается.
- `prefers-reduced-motion` отключает анимации; статус доступен текстом.

## Меню и мастер

Меню аккаунта: **«Проверить подключение»** с подсказкой в одну строку
«Проверит доступ и обновит занятое место» (проверяет доступ и обновляет
занятое место), затем **«Выйти»** (danger, подтверждение). Пункта
«Войти заново» нет: повторный вход — через «Выйти».

Мастер подключения — три шага: **«Подключение»** → **«Папка на сервере»** →
**«Готово»**. Состав первого шага зависит от `GET /api/oauth/yandex/status`:

- `available: true` — первым сегментом во всю ширину **«Войти через Яндекс»**
  (выбран по умолчанию), под ним двумя равными сегментами запасные
  **«Логин и пароль приложения»** и **«Вход по токену»**;
- `available: false`, старый сервер или ошибка статуса — способ не показывается,
  экран прежний: два равноправных сегмента, по умолчанию пароль.

Статус запрашивается на старте мастера, ответ запоминается на сессию: при
повторном открытии Яндекс-способ выбран сразу, без мигания. Переключение
способов сохраняет введённые логин, пароль и токен. Нижних ссылок
«Вернуться к логину и паролю» / «Вставить готовый токен» нет. Подсказки
сокращены до действий, без которых пользователь ошибётся: для пароля — тариф
**Яндекс 360** и активация через **2–3 часа**; для токена — обязательность
**refresh-токена**. Технические пояснения о хранении данных и общие
предупреждения с основного экрана убраны.

### Вход через Яндекс

Вход по коду подтверждения (device flow): токен хранит и аккаунт создаёт
сервер, интерфейс не получает ни пароль, ни токен. Пока код не получен,
панель — пояснение (код действует 10 минут, пароль приложения не нужен,
подтвердить можно с телефона) и primary-кнопка **«Получить код»**; футерная
«Подключиться» на этом способе скрыта, «Отмена» закрывает мастер.

| Состояние | Экран |
|---|---|
| код получен | панель с крупным кодом `XXXX-XXXX` (моно 30 px, выделяется целиком), ссылкой **https://oauth.yandex.ru/device** в новой вкладке, строкой «Код действует 10:00», кнопкой **«Отменить»** и `role="status"`-строкой «Ждём подтверждение…» |
| `done` | панель закрывается, мастер переходит на шаг «Папка на сервере»; повторный `POST /api/accounts` не отправляется |
| `error` | янтарная панель с сообщением сервера и primary **«Получить новый код»**, фокус на ней |
| `404` или истёк таймер | «Код истёк» и **«Получить новый код»**, фокус на кнопке |
| `429` | «Слишком много попыток, подождите минуту.» и кнопка повтора в фокусе |
| сеть или 5xx при опросе | «Нет связи. Повторяем…», поток сохраняется, опрос продолжается |

- `POST /api/oauth/yandex/device/start` отправляет `{name: "Яндекс Диск"}`;
  подтверждение проверяется через `GET /api/oauth/yandex/device/{id}` каждые
  **5 секунд**, таймер обратного отсчёта идёт от `expiresIn` с шагом 1 секунда;
  по нулю таймер и опрос останавливаются.
- «Отменить» на экране кода удаляет поток и возвращает к «Получить код».
  Переход на другой способ, уход из мастера, `hashchange` на главный экран и
  закрытие вкладки (`pagehide`, keepalive) отправляют
  `DELETE /api/oauth/yandex/device/{id}` и останавливают таймеры.
- Доступность: код получает программный фокус после получения, кнопка повтора —
  после ошибки или истечения; строка статуса создаётся пустой и заполняется
  после вставки, поэтому `role="status"` + `aria-live="polite"` озвучивает
  каждую смену; «Отменить» — обычная кнопка, доступная с клавиатуры.

Токен:

- рядом с полем — компактная кнопка **«Как получить токен?»**, раскрывающая
  пошаговую инструкцию на месте;
- шаги самодостаточны: создать приложение на `oauth.yandex.ru` с доступом
  `cloud_api:disk.read`; открыть
  `https://oauth.yandex.ru/authorize?response_type=code&client_id=…`;
  обменять код командой в `<code>` с кнопкой «Скопировать»; вставить JSON.

Экран успеха — только **«Готово, диск подключён»** и кнопка
**«Перейти к скачиванию»**. Путь к папке виден на предыдущем шаге, поэтому
здесь нет ни пути, ни кнопки «Изменить папку», ни возврата назад.

## Выбор папок

Поле «Из облака» — компактная кнопка-сводка `.source-summary`: иконка облака,
значение и действие. Она не растягивается на всю строку: `inline-flex`,
ширина по содержимому + padding, выравнивание по левому краю, справа —
«Выбрать» / «Изменить». Состояния: `0` → «Весь Диск» + «Выбрать»;
`1` → `/Фотографии` + «Изменить»; `>1` → «3 папки» + «Изменить», полный
список — в `title`. Число и слово разделены неразрывным пробелом;
плюрализация `папка/папки/папок`. Выбор облака для скачивания живёт в
диалоге «Новое скачивание» (ниже), а не в мастере подключения.

## Осознанные решения

- Только светлая тема: продукт сознательно не переключается в тёмную.
- Нет RTL и полной локализации: интерфейс на русском, строки в JS/HTML.
- Скрытых жестов нет: всё доступно мышью и клавиатурой.
- Один аккаунт Яндекс Диска: подключение нового заменяет текущий.
- Только копирование: удаление файлов не выполняется ни в одном сценарии,
  синхронизация с удалением — будущая итерация (API уже принимает `sync`).
- Размеры папок необязательны: без `POST /api/cloud/sizes` интерфейс работает
  без них и не показывает заглушек; размеры — подсказка, а не условие выбора.
- Инструкция по токену не уводит на сторонние «как это сделать» сайты:
  все шаги, ссылка авторизации и команда обмена — на экране.
- Вход через Яндекс работает на серверных кредах: интерфейс не присылает
  `client_id`/`client_secret` и не хранит токен — его пишет сервер, аккаунт
  создаётся до перехода на шаг выбора папки. Если сервер не настроен
  (`available:false`), способ не показывается и не предлагается.
- Пароль приложения и токен остаются полноценными запасными способами: они
  доступны на том же шаге, но ниже Яндекс-входа, когда тот доступен.
