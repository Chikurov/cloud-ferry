# Флоу Cloud Ferry: текущие сценарии

Состояние: `0.3.1`, flow v3 (три шага, панель аккаунта, офлайн-полоса).
Источник истины — `internal/httpapi/web/{index.html,app.js}`; проверочные
скриншоты — [`final10/`](final10/), отчёт v3 — [`flow-v3-apply.md`](flow-v3-apply.md).
Оценка трения: 1 — гладко, 5 — пользователь может не дойти до цели.

## 0. Запуск

Открытие ярлыка → `GET /api/state` и `GET /api/system` → скелет оболочки с
шапкой и контурами трёх ячеек → главный экран. Скелет держит места ячеек,
поэтому после ответа макет не прыгает. Если сервер не ответил, интерфейс не
заменяется отдельным экраном: сверху появляется полоса «Нет связи с сервером».

## 1. Подключение диска

**Шаги:** плитка «Подключить диск» → шаг 1 «Подключение» → способ →
«Подключиться» → шаг 2 «Папка на сервере» → «Обзор» или путь → «Продолжить» →
шаг 3 «Готово, диск подключён» → «Перейти к скачиванию».

**Способы:**

- **«Войти через Яндекс»** — только если сервер настроен со своим приложением.
  Код `ABCD-1234`, страница `oauth.yandex.ru/device`, код живёт 10 минут,
  подтверждение проверяется каждые 5 секунд. Пароль приложения не нужен.
- **«Логин и пароль приложения»** — требует Яндекс 360. Неверный пароль
  показывается как неверные данные. Форма сохраняет логин между способами,
  пароль можно показать.
- **«Вход по токену»** — поле и раскрывающаяся инструкция «Как получить токен?»:
  приложение на `oauth.yandex.ru`, доступ `cloud_api:disk.read`, обмен кода на
  токен командой, вставка JSON. Нужен `refresh_token`.

**Трение (3/5):**

- Пароль приложения — барьер: без Яндекс 360 он не работает.
- Токен — технический путь: создать приложение, получить код, выполнить curl,
  скопировать JSON.
- Шаг 2 без контекста: «Папка на сервере» — это папка Umbrel, куда лягут файлы;
  на шаге нет пояснения об этом.

## 2. Ошибки подключения

Ошибка показывается под полем или над кнопками, с фокусом на проблемном поле.

| Причина | Сообщение |
|---|---|
| Неверные данные | «Неверный логин или пароль приложения. Проверьте данные из Яндекс ID» |
| Нет 360 | «WebDAV недоступен — нужен Яндекс 360» |
| Плохой токен | «Токен не подошёл или истёк. Проверьте, что скопировали его целиком» |
| Токен без JSON-поля | «В JSON нет поля access_token» |
| Сервер молчит | «Сервер не ответил — попробуйте ещё раз» |

**Трение (2/5):** тексты понятные, но сообщение «нужен Яндекс 360» не подсказывает,
что можно сразу переключиться на «Вход по токену».

## 3. Первый экран без аккаунта

Одна плитка **«Подключить диск»**. Минимум решений, один путь — в мастер
подключения.

## 4. Новое скачивание

**Вход:** «Скачать» на главном. Один диалог, три шага, в шапке один раз
«Новое скачивание» и позиция «N из 3».

### Шаг 1. «Куда сохранить»

Одна навигационная строка: вверх, текущий путь, «Создать папку». Строка папки
открывает вложенную; форма создания — инлайн, с ошибками «Введите название
папки» и «Папка с таким именем уже есть». Пустая папка — допустимое место.
Футер: «Выбрать эту папку»; при редактировании из проверки — «Сохранить папку»
и «Назад». Свободное место здесь не показывается.

### Шаг 2. «Что скачать»

- Фильтр **«Показать уже скачанные»** по умолчанию включён, все папки видны.
  Меню **«Ещё»** стоит в той же строке над деревом.
- Дерево: чекбокс, имя, метаданные, кнопка файлов (глаз), раскрытие вложенных.
- Смешанный чекбокс = частичный выбор; клик по нему открывает подтверждение
  «Выбрать всю папку «…»?» с «Выбрать всю» / «Отмена», а не расширяет выбор.
- Теги: «Папка есть на сервере», «Пустая папка на сервере», «Входит в выбранную
  папку». Первые два — факт наличия папки, не полноты скачивания. Обещания
  перезаписи нет.
- Панель файлов: «Выбрать все файлы», отдельные файлы, «К папкам». При
  `truncated` — «Показаны первые 200 файлов. Чтобы скачать всё, выберите папку».
- Лимиты: 20 папок и 100 файлов, считаются после нормализации. Сообщение —
  в зарезервированной строке над футером; выбор при превышении не меняется.
- «Весь диск» — пункт меню «Ещё»; в этом режиме кнопка меню показывает «Весь
  диск», пункт — «Выбрать вручную». Открытие меню режим не меняет.

### Шаг 3. «Проверьте выбор»

Сводка: «Источник» (чипы, «Изменить»), «Папка на сервере» («Изменить»),
«К скачиванию», «Свободно», примечание «Существующие файлы не удаляются».
Оценка стартует автоматически; состояния — «Считаем объём…», «Оценка ещё идёт»
(после 20 с), готовый объём, «Не хватает …» с блокировкой «Скачать», частичная
оценка, ошибка/таймаут. При запуске — «Запускаем…», при потере ответа —
«Проверяем, началось ли скачивание…» и повтор с тем же ключом, поэтому вторая
задача не создаётся.

**Трение (2/5):**

- Фильтр меняет только видимость; выбранное остаётся видимым, но это правило
  не объяснено в интерфейсе.
- Отдельные файлы не помечаются «уже скачано»: `/api/jobs/existing` принимает
  только папки.
- Закрытие окна и уход со шага обрывают запрос оценки в браузере. Останавливается
  ли обход внутри rclone, не проверено.
- Сокращённого входа с последней папкой нет: каждый запуск начинается с шага 1.

## 5. Активное скачивание

Карточка «Сейчас»: статус, процент, полоса, скорость и остаток, «Приостановить»,
строка «3 папки · 12,4 из 29,0 ГБ → /downloads». Пока `totalBytes = 0`, процент
заменён на «Считаем…», полоса — indeterminate.

**Трение:** нет; при неизвестном объёме хотя бы честно сказано, что объём
считается.

## 6. Пауза и продолжение

Одна кнопка по состоянию: «Приостановить» → «Продолжить». Пауза ставит статус
«Пауза»; скачанные файлы не перекачиваются, недокачанный файл начинается
заново (поведение rclone). Постановка на паузу может занять время — тогда
тост «Скачивание приостановлено не сразу».

**Трение (2/5):** недокачанный файл после паузы скачивается заново; для больших
файлов это заметно.

## 7. Ошибка скачивания

Статус «Не удалось», заголовок и совет из движка, «Не скачались: N», список
файлов (до 200), «Скопировать список», «Повторить».

**Трение (2/5):** «Повторить» запускает задачу целиком; отдельного повтора
только для неудачных файлов нет.

## 8. Аккаунт и место

Чип в шапке открывает панель: логин, способ входа, доступ и время проверки,
занятое место на Диске, свободное место на сервере и папка назначения, кнопки
«Проверить» и «Войти заново», отдельный блок «Выйти». Если данные о месте
старше 5 минут — пометка «последние данные»; если проверки не было — «Нажмите
«Проверить», чтобы узнать занятое место».

**Трение:** нет; проверка и квота в одном месте.

## 9. Выход

«Выйти» внизу панели → подтверждение «Выйти из Яндекс Диска?» с текстом, что
активное скачивание остановится, а файлы останутся. После выхода аккаунт
удаляется, приложение возвращает к плитке «Подключить диск».

**Трение (2/5):** не сказано, что будет с недокачанными файлами и что историю
заданий после выхода не вернуть.

## 10. Офлайн

Вместо отдельного экрана — полоса под шапкой: «Нет связи с сервером», «Показаны
последние данные», «Повторить»; в шапке — точка. Ячейки сохраняют последние
данные, фокус не переводится. Опрос идёт с backoff до 30 секунд, на скрытой
вкладке останавливается.

## 11. Восстановление после перезапуска

Состояние задач лежит в `state.json`. После старта: завершившаяся задача
получает настоящий результат, идущая — подхватывается, остальные помечаются
«Пауза» с кнопкой «Продолжить». Пользователь видит либо «Готово», либо «Пауза»,
а не вечное «Идёт скачивание».

**Трение (2/5):** после перезапуска всё равно нужно нажать «Продолжить»;
недокачанный файл начнётся заново.

## 12. Мобильный

Окно «Новое скачивание» на экране ≤640 px — полноэкранный лист: шапка и футер на
месте, прокручивается только тело; путь занимает отдельную строку, кнопки
44 px, панель файлов раскрывается под папкой, дата файла скрыта, кнопки внизу на
всю ширину. Главный экран ставит ячейки друг под другом, панель аккаунта — лист
на всю ширину. Шаги, статусы и тексты те же.

## Сквозные наблюдения

1. **Словарь.** В интерфейсе только «скачивание», «Пауза»,
   «Приостановить»/«Продолжить», «Нет связи с сервером»; технические пути и
   коды пользователю не показываются.
2. **Один аккаунт.** При новом подключении старый аккаунт заменяется; история
   заданий от него в интерфейсе не показывается.
3. **Нет истории.** Видна только активная или последняя задача; вернуться к
   прошлому заданию нельзя.
4. **Оценка объёма.** Автоматическая. Закрытие окна обрывает запрос в браузере.
   Обход внутри rclone после отмены HTTP не проверен.
5. **Большие списки.** Дерево обрезается на 500 папках, файлы — на 200, без
   курсора; следующую страницу получить нельзя.

## Что осталось

- **P1.** Сокращённый вход с последней доступной папкой — сразу шаг 2.
- **P1.** Отметка отдельных файлов «уже скачано» — нужен серверный ответ по
  файлам, а не только по папкам.
- **P2.** Отмена серверной оценки объёма и подгрузка следующих страниц
  дерева/файлов.
- **P2.** Повтор только для неудачных файлов и экран истории задач.
