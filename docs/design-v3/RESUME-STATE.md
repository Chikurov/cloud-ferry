Дата: 18 ноября 2026. Задача: `task-13`.
Scope: `internal/jobs/manager.go`, `internal/store/store.go`, `internal/httpapi/web/{app.js,style.css}`, `docs/design-v3`.
Коммит не делался.

## 1. Что изменено

### 1.1. Backend: прогресс переживает паузу и продолжение

Причина исходного дефекта: `Resume` писал `j.Stats = store.Stats{}`, поэтому до
первого опроса карточка показывала 0 %, а подпись «Начинается» усиливала
ощущение, что скачивание началось заново. Кроме того, rclone считает статистику
каждого engine-задания отдельно: после продолжения `core/stats` присылает только
остаток, и процент пересчитывался от меньшего знаменателя — цифры прыгали
(70, 80, 40, снова растёт — это были гигабайты, а не проценты).

`internal/store/store.go` — новое поле задачи:

- `BytesBase int64` с тегом `json:"bytesBase,omitempty"`: сколько байт уже
  скачано к моменту возобновления. У новых задач 0, в `state.json` не пишется,
  старые state-файлы читаются как раньше.

`internal/jobs/manager.go`:

- `Resume`: вместо обнуления Stats — `j.BytesBase = j.Stats.Bytes`; сохраняются
  `Bytes`, `TotalBytes`, `Transfers`, `TotalTransfers`; обнуляются только
  живые величины `Speed`, `ETA`, `Errors`, `ElapsedTime`. Карточка сохраняет
  прошлый процент, пока не придёт первый свежий опрос.
- `pollOne`: статистика стала кумулятивной —
  `Bytes = BytesBase + stats.Bytes`,
  `TotalBytes = max(прежний TotalBytes, BytesBase + stats.TotalBytes)`.
  Ни байты, ни знаменатель не уменьшаются: процент обязан быть монотонным,
  допускается «замирание».
- `Start` не менялся: у новой задачи `BytesBase` равен нулю по умолчанию.

### 1.2. UI: состояния карточки

| Состояние задачи | Подпись | Полоса |
|---|---|---|
| `queued`, новая задача | «Начинается» | 0 %, бегущий блик |
| `queued`, задача возобновлена (в этой сессии или `bytesBase > 0`) | «Продолжаем…» | прошлый процент приглушён + блик |
| `running`, `elapsedTime == 0` или ещё нет новых байт относительно `bytesBase` | «Проверяем, что уже скачано…» | прошлый процент + анимированный блик |
| `running` с первым свежим пакетом байт | скорость · ETA | живой процент |
| `interrupted` / `canceled` | «Пауза» | процент паузы (приглушённая полоса) |
| `done` | «Завершена» | 100 %, полный объём |

В карточке впервые виден сам процент: «40 % · 4,8 из 12,0 ГБ», у завершённой —
«100 % · 12 ГБ» (файлы на месте; разница с планом — уже существовавшие файлы,
которые rclone пропустил).

`internal/httpapi/web/app.js`:

- `shownPercent()` — процент только растёт: держит нижнюю границу по задаче,
  поэтому запоздавший меньший ответ не откатывает полосу;
- `jobBaseBytes()` / `jobPreparing()` / `jobStateText()` — новая логика подписи;
  признак «первый свежий пакет пришёл» — `stats.bytes > bytesBase`;
- `jobProgressText()` — процент и объём в карточке; у `done` — полный объём;
- `renderJobList()` — вместо нативного `<progress>` кастомная полоса
  `role="progressbar"` с `aria-valuenow`/`aria-valuetext`; класс
  `progress--prepare` включает indeterminate-анимацию; у кнопки в `queued`
  выставляется `aria-busy="true"`;
- `resumeJob()` — после подтверждённого ответа запоминает задачу как
  возобновлённую и фиксирует нижнюю границу процента; уборка при
  «Убрать из списка».

### 1.3. CSS

- Полоса карточки: высота 4 px, при подготовке прошлый процент остаётся
  видимым (`fill` с `opacity:.45`), по треку бежит блик
  (`@keyframes job-progress-scan`, 1.5 s, `infinite`);
- `prefers-reduced-motion: reduce`: анимация выключается, вместо движения —
  спокойная полупрозрачная подсветка трека, состояние читается текстом;
- `aria-busy` на кнопке карточки больше не включает общий busy-спиннер и не
  отключает указатель: «Приостановить» в очереди остаётся доступной и
  срабатывает;
- «Пауза» по-прежнему приглушает полосу, у `done` заливка зелёная.

## 4. Кумулятивные байты (дополнение из живого теста 0.4.0)

Симптом: выбрал «весь диск» (оценка 160 ГБ), остановил и продолжил — в карточке
сначала 70, потом 80, 40 и снова рост; подпись «Загрузка начинается».

Причина: после `Resume` rclone начинает новый engine-job, и его `totalBytes` —
это только остаток, а не весь план; процент считался от нового, меньшего
знаменателя.

Исправление (пункты 1–4 дополнения к задаче):

1. `store.Job.BytesBase` — сколько скачано к моменту возобновления; в `Resume`
   ставится `BytesBase = Stats.Bytes`, у `Start` — 0;
2. `pollOne` считает кумулятивно: `Bytes = BytesBase + stats.Bytes`,
   `TotalBytes = max(prevTotalBytes, BytesBase + stats.TotalBytes)`; оба
   значения не убывают;
3. UI берёт процент из этих значений и дополнительно держит нижнюю границу
   (`shownPercent`), поэтому между опросами процент не уменьшается;
4. у `done` карточка показывает 100 % и полный объём (`totalBytes`), даже если
   `stats.bytes < stats.totalBytes`: остаток — это уже существовавшие файлы,
   которые rclone пропустил. На реальном прогоне: `bytes = 8,1 ГБ` из
   `totalBytes = 12 ГБ`, карточка — «100 % · 12 ГБ».

Регрессионный тест `TestResumeKeepsProgressAndCountsCumulatively` проверяет
старт → паузу на 40 % → продолжение → опросы с остатком → ответ с меньшими
числами → завершение: байты кумулятивны, знаменатель не уменьшается, финальное
состояние `done`.

## 5. Решения и границы

- **«Приглушённый прошлый процент»** сделан полосой: заливка старого процента
  остаётся на месте с `opacity:.45`, поверх идёт бегущий блик. Текст
  «40 % · 4,8 из 12,0 ГБ» остаётся контрастным (`--muted` в обеих темах,
  новых цветов не добавлено) — прятать его прозрачностью было бы хуже для
  доступности.
- **«Продолжаем…» — короткое состояние.** Реальный backend переводит задачу из
  очереди в `running` сразу после запуска engine, поэтому в жизни пользователь
  чаще увидит «Проверяем, что уже скачано…»; очередь проверена на mock-стенде.
- **Счётчики файлов не накапливаются.** `Transfers`/`TotalTransfers` после
  продолжения приходят от нового engine-job. В карточке они не показываются
  (у «Готово» — объём), но если понадобится число файлов за все попытки, нужен
  отдельный `TransfersBase` — в задаче этого не было.
- **Найден существующий дефект вне scope.** Реальный сервер отдаёт
  `Content-Security-Policy: script-src 'self'`, из-за чего inline-скрипт темы в
  `index.html` блокируется (2 предупреждения CSP в консоли). К task-13 не
  относится, приложение работает; трогать CSP в этой задаче не стал.
  В `docs/USER-GUIDE.md` строка «в начале — «Начинается»» теперь описывает
  только очередь — гайд вне scope, стоит поправить отдельно.
- **Стенд.** Матрица снята на mock-API (реальные `index.html`/`style.css`/
  `app.js`) — так состояния детерминированы. Кумулятивность дополнительно
  проверена на реальном Go-backend с fake rclone; настоящий Яндекс.Диск и
  настоящий rclone не использовались.
- Изменены только `internal/store/store.go`, `internal/jobs/manager.go`,
  `internal/jobs/resume_progress_test.go` (новый), `internal/httpapi/web/app.js`,
  `internal/httpapi/web/style.css`; добавлены отчёт, скриншоты и evidence.
  Рабочие файлы стенда лежат вне репозитория:
  `agent-work/resume-state/{mock.py,fake_rclone_resume.py,test.mjs,e2e.mjs}`.
