# Архитектура флоу Cloud Ferry

Цель — не 13 отдельных сценариев, а четыре понятных пути и один слой системных
состояний. Критерий: пользователь в каждый момент понимает, где он, что
происходит и что будет дальше.

Состояние: реализовано в `0.3.1` (flow v3). Проверки и скриншоты —
[`flow-v3-apply.md`](flow-v3-apply.md), [`final10/`](final10/); пошаговое
описание — [`flows.md`](flows.md).

## Принципы

1. **Один экран — одна задача.** Если на экране две цели (место на Диске и
   свободное место на сервере), это два блока, а не два экрана.
2. **Состояния — не флоу.** Загрузка, офлайн, пауза, ошибка — состояния пути, а
   не отдельные сценарии.
3. **Один вход — один выход.** У каждого пути есть явная точка входа и понятный
   финал.
4. **Разные задачи — разный вид.** Мультивыбор папок и выбор одной папки не
   выглядят одинаково.
5. **Не плодить экраны.** Новый экран оправдан, только если меняется задача, а не
   статус.

## Решения по флоу

| Флоу | Решение | Как сделано |
|---|---|---|
| Запуск | слить в оболочку | скелет шапки и ячеек, офлайн — полосой |
| Подключение | оставить, слить с повторным входом | мастер из 3 шагов, «Войти заново» ведёт в него же |
| Ошибки подключения | слить в шаг подключения | ошибка у поля или над кнопками, без отдельного экрана |
| Первый экран | слить с подключением | плитка «Подключить диск» — вход в мастер |
| Новое скачивание | разделить на 3 шага | назначение → источник → проверка |
| Активное скачивание | слить с запуском | следующее состояние ячейки «Сейчас» |
| Пауза/продолжение | одна кнопка по состоянию | «Приостановить» / «Продолжить» |
| Ошибка скачивания | слить в результат | «Не удалось» + причина + список + «Повторить» |
| Проверка подключения | слить в аккаунт | кнопка «Проверить» в панели, статус виден всегда |
| Выход | отделить от безопасных действий | отдельный блок внизу панели + подтверждение |
| Хранилище | два места показа | квота — в аккаунте, свободное место — в шаге назначения и аккаунте |
| Восстановление | слить с состоянием задачи | «Пауза» + «Продолжить» |
| Офлайн | слить в оболочку | полоса «Нет связи», данные остаются |

## Пути

### П1. Подключение диска

Вход: плитка «Подключить диск», «Войти заново» или первый запуск.
Шаги: **«Подключение»** → **«Папка на сервере»** → **«Готово, диск подключён»**.

- Способы: «Яндекс ID» (если сервер настроен), «Логин и пароль
  приложения», «Токен».
- Состояния: проверка доступа, ошибка у поля, ожидание активации пароля,
  ожидание кода, истёкший код.
- Финал: главный экран с аккаунтом и тост о подключении.

Отличие от прежней схемы: три шага и проверка доступа до создания аккаунта;
отдельного экрана проверки подключения нет.

### П2. Скачивание

Вход: «Скачать» на главном.
Шаги:

1. **«Куда сохранить»** — одна папка на сервере, создание папки инлайн.
2. **«Что скачать»** — весь диск или папки и файлы; фильтр «Показать уже
   скачанные» включён по умолчанию; теги «Папка есть на сервере» и «Пустая
   папка на сервере»; лимиты 20/100.
3. **«Проверьте выбор»** — источник, папка, объём и свободное место,
   «Изменить» у каждой строки, «Скачать». Запуск идёт с ключом идемпотентности:
   повтор после потери ответа не создаёт вторую задачу.

После запуска — та же ячейка «Сейчас»: «В очереди», «Идёт скачивание», «Пауза»,
«Готово», «Не удалось». Ошибка и частичный результат — один экран итога.

Отличие от прежней схемы: назначение и источник — разные шаги с разным
поведением (одна папка / мультивыбор), а фильтр существующего не меняет выбор и
payload.

### П3. Аккаунт и место

Вход: чип аккаунта в шапке (и карточка «Аккаунт» на главном).
Содержимое: логин, способ входа, доступ и время проверки, занятое место на
Диске, свободное место на сервере и папка назначения, «Проверить», «Войти
заново», отдельный красный блок «Выйти» с подтверждением.
Финал: выход возвращает к плитке «Подключить диск».

Отличие от прежней схемы: проверка подключения и квота — в одном месте, опасное
действие отделено от безопасных.

### П4. Системные состояния

Не путь, а слой:

- загрузка — скелет оболочки;
- офлайн — полоса сверху, данные остаются последними;
- восстановление после перезапуска — статус «Пауза» с кнопкой «Продолжить»;
- устаревшие данные — пометка «последние данные» с временем проверки.

## Карта экранов

```
Оболочка (шапка + полоса состояния)
├─ Главный экран
│   ├─ Сейчас       — состояние задачи, одно действие
│   ├─ Скачать      — вход в П2
│   └─ Аккаунт      — карточка-вход в П3
├─ П1 Подключение   — 3 шага
├─ П2 Скачивание    — 3 шага + итог
└─ П3 Аккаунт       — панель, не экран
```

## Что убрано

- Отдельный экран «Нет связи» — заменён полосой.
- Отдельная ячейка «Хранилище» — место разделено между аккаунтом и шагом
  назначения.
- Полоски шагов и подпись «Шаг N из 3» в диалоге — одно обозначение «N из 3».
- Подсказка «Нажмите на строку…» и тулбар «Содержимое» — одна навигационная
  строка.
- Кнопки «Приостановить» и «Продолжить» одновременно — одна кнопка по
  состоянию.
- Диалоги «Из облака» и «На сервере» как два похожих дерева — три шага одного
  диалога с разными задачами.
- Постоянный счётчик выбора, подписи «Домашний сервер», «Режим», «Добавлять
  новые файлы», «Далее»/«Сохранить сюда».

## Что осталось

- **P1. Короткий вход.** Повторный вход начинается с сохранённого пути, но
  всё равно с шага 1.
- **P1. Отметка файлов.** `/api/jobs/existing` отвечает по папкам, поэтому
  отдельные файлы не получают «уже скачано».
- **P2. Отмена оценки.** Серверный обход `operations/size` не отменяется.
- **P2. Пагинация.** Дерево и файлы приходят с `truncated`, без курсора.
- **P2. Повтор части файлов.** «Повторить» перезапускает задачу целиком.
- **P2. История.** Экрана истории задач нет, видна только последняя.
