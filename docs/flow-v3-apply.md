## Что сделано по пунктам P0

### 1. Шапка диалога
- «Новое скачивание» показывается один раз, в шапке диалога (`#flow-title`).
- Внутри тела — короткий заголовок шага и одно обозначение позиции: «1 из 3», «2 из 3», «3 из 3».
- Полоски шагов и подпись «Шаг N из 3» удалены.
- В контексте мастера (пикер папки в setup) заголовок «Папка на сервере», номер шага и заголовок шага не показываются.

### 2. Назначение
- Одна навигационная строка: кнопка вверх (иконка, доступное имя «На уровень выше»), путь, «Создать папку».
- На телефоне путь переносится на отдельную строку, кнопки остаются доступны.
- Убраны подсказка «Нажмите на строку…», тулбар «Содержимое» и дублирующий путь.
- Основная кнопка — «Выбрать эту папку»; при входе из проверки — «Сохранить папку» и «Назад» к сводке.
- Свободное место на шаге не выводится.
- После создания папка открывается, фокус переходит на основную кнопку подтверждения.

### 3. Источник
- «Выбрать весь диск» убрано из основного ряда в меню «Ещё» (кнопка с тремя точками).
- Открытие меню режим не меняет; режим переключает только пункт меню.
- В режиме «Весь диск» кнопка меню показывает «Весь диск», пункт — «Выбрать вручную».
- Фильтр и меню находятся в одной компактной строке над деревом.

### 4. Фильтр и политика
- «Показать уже скачанные» меняет только видимость уже известных позиций и не участвует в выборе/payload.
- При выключенном фильтре скрываются **невыбранные** известные совпадения; уже выбранные остаются видимыми, чтобы выбор не выглядел потерянным. Это единственное исключение из «только видимость» и оно объяснимо: снятие выбора остаётся доступным.
- Переключение фильтра не сбрасывает выбор; выбранную уже скачанную папку можно снять.
- Тег «Уже на сервере» — факт с сервера; обещания «Будет перекачано» и отдельного действия «Скачать заново» нет, пока сервер не подтверждает политику пропуска/перезаписи.
- Проверено: payload `POST /api/preflight` не зависит от состояния фильтра.

### 5. Три состояния дерева
- Смешанный чекбокс = частичный выбор (indeterminate, aria-label «часть содержимого выбрана. Выбрать всю папку»).
- Клик по смешанному чекбоксу не расширяет выбор: открывается компактное подтверждение «Выбрать всю папку «…»?» с действиями «Выбрать всю» / «Отмена».
- Chrome переключает `checked` до события `click`, поэтому решение принимается по модели выбора, а не по DOM-флагу; запоздавший `change` гасится.
- «Отмена» и Esc закрывают подтверждение и возвращают фокус на чекбокс.
- Снять выбор с выбранной папки/файла можно сразу, без подтверждения.
- Потомки выбранного корня показываются выбранными и недоступными, отдельно в лимитах не считаются.

### 6. Лимиты
- Лимит считается на нормализованном итоговом выборе до применения: явные корни папок сворачиваются, файлы под выбранными корнями не занимают отдельные места.
- Тексты ровно по аудиту: «Можно выбрать не больше 20 папок» и «Можно выбрать не больше 100 отдельных файлов».
- Сообщение показывается в зарезервированной зоне над кнопками футера (зона не прыгает), с переносом текста.
- При 21-й папке/101-м файле выбор не меняется, фокус остаётся на попытке; «Назад», «Проверить выбор», «Закрыть» и снятие выбора продолжают работать.
- «Выбрать все файлы» добавляет столько, сколько помещается, и показывает тот же текст лимита.
- Лимит озвучивается один раз через live-region диалога.

### 7. Сводка шага 3
- Две строки: «Источник» и «Папка на сервере», у каждой «Изменить».
- Дальше — «К скачиванию» и «Свободно»; примечание «Существующие файлы не удаляются».
- Убраны подписи «Куда», «Режим», «Добавлять новые файлы», «Домашний сервер», «Выберите одну папку…», «Места достаточно», отдельная карточка объёма и дублирующий footnote.
- «Изменить» источника/папки возвращает на нужный шаг и после подтверждения ведёт обратно к сводке; выбор сохраняется.

### 8. Оценка объёма
- Автозапуск при входе на шаг 3 по текущему нормализованному выбору; повторный вход с тем же выбором не создаёт второй POST.
- Состояния: «Считаем объём…», после 20 с — «Оценка ещё идёт»; успех — «N файлов · объём»; «Не хватает X» (с блокировкой «Скачать»); «Часть файлов не удалось оценить» + «Повторить оценку»; «Не удалось оценить объём» + «Повторить».
- Частичный результат распознаётся по `partial: true` или `unknownFiles > 0` (контракт — в разделе backend).
- Смена выбора/назначения отменяет ожидание старого ответа (abort + ключ + seq); старый результат не перетирает новый.
- «Свободно» берётся из preflight, при его отсутствии — из данных шага 1.

### 9. Запуск
- Состояние «Запускаем…» в зоне над футером, спиннер на основной кнопке; «Назад» и «Закрыть» на время запуска заблокированы.
- При потере ответа (timeout/network) — «Проверяем, началось ли скачивание…» и сверка по `GET /api/state`: новый job с тем же путём и свежим `createdAt`; при подтверждении диалог закрывается, при отсутствии — сообщение «Проверьте «Сейчас»».
- Приложение отправляет один POST на действие; собственного автоматического повтора нет. Ожидаемые повторы транспорта Chrome после обрыва соединения — отдельный backend-риск (см. ниже).

### 10. Визуальная гармонизация
- Одна синяя основная кнопка на представление; в форме создания папки вторая синяя кнопка убрана.
- «N из 3» без полосок; тонкие разделители строк сводки, hairline шапки/футера; никаких постоянных счётчиков и лишних подписей.
- Проверены 1440, 1000, 500 (200 % текста), 390 и 320 px; `scrollWidth === innerWidth` на всех.
- Фокус после навигации — на заголовке шага; после лимита — на попытке; после повтора оценки — в сводке; после закрытия — на «Скачать».
- Устранён побочный дефект: при фокусе на 101-м файле сам `<dialog>` прокручивался и шапка/футер уезжали. Теперь `overflow: clip` и позиционирование чекбоксов относительно строки, прокручивается только тело.

## Требует backend (не выдумано во фронтенде)

Ниже — точные контракты, без которых соответствующие состояния нельзя сделать честно.

1. **Идемпотентный запуск.** Backend-контракт уже вводится параллельной задачей:
   `POST /api/jobs` принимает `Idempotency-Key` (8–128 символов `[A-Za-z0-9._:-]`) или поле `clientToken` в теле; повтор с тем же ключом и тем же payload возвращает исходную задачу (`200` + `Idempotent-Replay: true`) без создания новой; тот же ключ с другим payload — `409 { code: "idempotency_conflict", field: "Idempotency-Key" | "clientToken" }`; без ключа поведение прежнее.
   **Фронтенд этой задачей ключ не отправляет:** на действие один POST, потеря ответа проверяется через `GET /api/state`. Подключение ключа — следующий шаг (сгенерировать ключ на попытку и передать `clientToken`/заголовок). Без него транспортный повтор Chrome после обрыва может создать дубли (в моке наблюдали до 4 доставок одного действия).

2. **Детерминированная сверка запуска.**
   Сейчас фронтенд после потери ответа 4 раза читает `GET /api/state` и ищет новый job по `dest` + свежему `createdAt`. Нужен один из вариантов:
   - `GET /api/jobs/lookup?accountId=&destPath=&startedAfter=` → задача или `404`;
   - `POST /api/jobs` → `202 { operationId }` и `GET /api/operations/{id}`;
   - либо `GET /api/jobs/{id}` при синхронном id.
   Это убирает эвристику и ложные срабатывания на чужую старую задачу.

3. **Политика существующих файлов (skip/overwrite).**
   `mode=copy` не удаляет файлы, но rclone copy может перезаписать изменившиеся. Нужно:
   - поле `existing: "skip" | "overwrite"` в `POST /api/jobs` (и, если нужно, в preflight) с явным ответом сервера;
   - расширить `POST /api/jobs/existing`: к `{exists, entries}` добавить `filesSkipped`/`policy` и агрегат `existingFiles` по выбранным корням;
   - только после этого показывать «Уже есть на сервере: N» и отдельное действие повторного скачивания.
   Сейчас показывается только «Уже на сервере» и никакого обещания/отдельного действия нет.

4. **Отмена оценки.**
   `POST /api/preflight` должен возвращать `{ estimateId }` (или `202` + `Location`), а `DELETE /api/preflight/{estimateId}` — останавливать серверный обход (`operations/size`) и отвечать `202/204`. Фронтенд уже обрывает свой HTTP-запрос при смене выбора/закрытии, но серверная работа без отмены продолжается до 10 минут.

5. **Лимиты режима «Весь диск».**
   Пустой источник означает весь диск; лимиты 20 папок/100 файлов к нему сейчас не применяются. Нужно:
   - `GET /api/accounts/{id}/limits` → `{ maxFolders, maxFiles }` и/или проверка на `POST /api/preflight`/`POST /api/jobs` с ошибкой `400 { field: "sourcePaths", code: "too_many_folders" | "too_many_files" }`;
   - те же тексты, что на шаге 2. Без серверного подтверждения массовый режим оставлен как есть.

6. **Подгрузка файлов и папок.**
   `GET /api/accounts/{id}/files` отдаёт максимум 200 файлов и `truncated`, без курсора. Нужны `nextCursor`/`hasMore` (и аналогично для `/folders`, где дерево обрезается на 500 папках), чтобы показывать «Показать ещё» только при подтверждённой следующей странице. Сейчас при `truncated` показывается «Показаны первые N» и «Выбрать папку».

7. **Частичная оценка.**
   Добавить в `200` ответ `POST /api/preflight` поля `partial: true` и/или `unknownFiles: N` (при частичном результате `bytes` — нижняя граница). Без них фронтенд не может отличить полный объём от частичного; сейчас поддерживаются оба поля, но сервер их не отдаёт.

8. **Старт без полной оценки.**
   Нужно подтвердить, безопасен ли `POST /api/jobs`, когда объём неизвестен/частичен. Если да — зафиксировать это в контракте (сейчас «Скачать» остаётся доступной во время оценки/ошибки и сервер останавливается на 90 % места). Если нет — фронтенд должен блокировать старт до полной оценки; это изменение поведения.

9. **Точный подсчёт «уже есть на сервере».**
   `entries` в `/api/jobs/existing` — число элементов в папке назначения, а не число файлов, которые будут пропущены. Для честного «Уже есть на сервере: N» нужен `filesSkipped` (или эквивалент) на элемент и агрегат.

## Риски и ограничения

- **Ширина диалога** осталась 480 px (не 880 из аудита), панель файлов по-прежнему инлайн, а не сбоку на десктопе. Это вне перечисленных P0-пунктов; при необходимости — отдельный P1.
- **Нет сокращённого входа** с последней папкой (сразу шаг 2): не реализовано; текущий вход всегда начинает с шага 1. Это P1 аудита.
- **Нет агрегата «Уже есть на сервере: N»** и отдельного повторного скачивания: ждём серверную политику (см. п. 3 backend).
- **Оценка не отменяется на сервере**: уход/смена выбора только обрывает HTTP-запрос; серверный обход может продолжаться.
- **Запуск без идемпотентности**: при обрыве соединения возможны дубли задач; UI показывает состояние сверки и не повторяет POST сам, но транспортный повтор Chrome вне контроля фронтенда.
- **Запуск без полной оценки** разрешён: «Скачать» доступна во время подсчёта/ошибки. Это соответствует текущему серверному `transferLimit` (остановка на 90 % места), но требует подтверждения контрактом.
- **«Весь диск»** не ограничен клиентом; серверные лимиты этого режима не подтверждены.
- **Дерево/файлы обрезаются** на 500 папках и 200 файлах; «Показать ещё» появится только после появления курсора в API.
- **Фильтр «уже скачанные»** по умолчанию скрывает невыбранные совпадения; выбранные остаются видимыми (осознанно).
- **Проверка существующих** опирается на `POST /api/jobs/existing`; при 404/405 фильтр тихо отключается, теги не показываются.
- **Восстановление прокрутки** между шагами не сохраняется (сброс на верх шага); раскрытие дерева и выбор сохраняются.
- Go/API не менялись; изменения web лежат в рабочем дереве без коммита.
